# Synthetic annotator-scope workflow dataset

**Entirely artificial text, no patients, no copied clinical CAS, no real terminology release.**
The `990...` identifiers and labels are toy data, not valid terminology assertions. The three
Number/Date identifiers mirror the application's built-in concept rules. `policy.hdf5` is a
tiny test policy, **not** a usable SNOMED CT release. Dates in it are synthetic metadata.

The ZIP follows the `exportedproject.json`, `source/`, and `annotation/<document>/<annotator>`
layout of `../snomed_pp_project-fmatthies-2026-08-18-075955.zip`; none of its clinical text,
annotations, users, credentials, or logs are copied. Alice uses JSONCAS and Bob uses XMI.
Each of the three documents has both annotators and an empty `INITIAL_CAS.json`.
A shared type system includes `webanno.custom.Concept` (`id`, `literal`, `note`), sentences,
and tokens. This is tested as **input to this application's offline workflow**, not as a
validated native INCEpTION full-project restore; it contains no Java serialized `.ser` CAS.

## Files

| File | Purpose |
|---|---|
| `project.zip` | Original synthetic project, before any decisions are applied |
| `policy.hdf5` | Ten concepts, inclusion/exclusion lists, three historical association rows |
| `critical-findings.json` | Actual findings generated by the policy checker, for both annotators |
| `suggestions.json` | Actual structured historical suggestions, no BM25/ancestor fallback |
| `concept-rules.json` | Enabled built-in Number/Date rules, policy override allowed |
| `staged-decisions.json` | Example review: rules and historical condition selected; manual controls left pending |
| `expected.json` | Machine-readable expected counts, including Alice-only scope |

Precomputed artifacts have `metadata.annotators=[]`, meaning all annotators. Load the
matching `suggestions.json` before restoring `staged-decisions.json`; their original
suggestion indices belong together. Current GUI scope filters the imported review.
The staged decisions are **not a completed human review** and have not changed `project.zip`.

## Cases (present independently for Alice and Bob)

| Document / annotation | Original ID | Expected behavior |
|---|---|---|
| `rules.txt`: `42` | `410680006` | Inclusion-list finding; Number rule clears only ID, preserving literal ` 0042 ± ` |
| `rules.txt`: `2026-01-15` | `410671006` | Already included: **no finding**, but Date rule still replaces ID with `410672004` |
| `rules.txt`: `accepted control` | `990000002` | Included, active; unchanged, no finding |
| `automatic.txt`: `Legacy amber` | `990000101` | Inclusion-list finding; one selectable `REPLACED_BY` target `990000201`; historical automatic condition succeeds |
| `manual-controls.txt`: `Legacy cobalt` | `990000102` | Inclusion-list finding; two selectable historical targets (`990000202`, `990000203`); ambiguous, not automatically selected |
| `manual-controls.txt`: `Blocked violet` | `990000301` | Included but excluded; exclusion-list finding remains manual |
| `manual-controls.txt`: `Unknown silver` | `990000404` | Absent from the policy concepts; inclusion-list finding, no historical replacement |

Date property `410672004` exists and is active but is **not included**. Consequently the
Date rule demonstrates a real policy override. Turning that rule's **Override policy** off
must block its application. An override does not make the replacement policy-compliant:
a later ordinary policy check can still report Date property. No clinical correctness is implied.

## Run the full GUI workflow

For clean repeated experiments, copy this directory to a scratch directory first; the GUI
writes generated reports beside the selected project. Do not enable the INCEpTION API or upload.

1. Set **Data directory** to this directory (or the scratch copy). Select `project.zip` as
   **INCEpTION project ZIP** and `policy.hdf5` as **SNOMED HDF5**.
2. Choose **Policy rules**, and use target annotation type `webanno.custom.Concept`.
   Leave ignore-overlap types empty. Keep ID prefix `http://snomed.info/id/` and ID feature `id`.
3. Keep **Load annotators from ZIP** enabled. In tab 1, leave the annotator selection empty
   for both, or select only `alice` **before checking/applying rules**.
4. Click **Run policy check**.
5. In suggestion settings, disable **Semantic BM25 fallback** and **Historical ancestor fallback**,
   then **Apply suggestion settings**. No SNOGIT cache, hierarchy or network is needed.
   Keep historical association type `REPLACED_BY` enabled.
6. Expand **Concept rules**, leave the two default rules and overrides enabled, and click
   **Apply rules to review**. Alternatively load `concept-rules.json` first, then apply.
7. Click **Generate sanitization suggestions** using current-session findings.
8. In review, keep the historical automatic-condition type `REPLACED_BY` selected and click
   **Apply Conditions**. BM25 automatic selection should remain off.
9. Confirm that only Legacy amber is automatically selected by the condition. `automatic.txt`
   becomes automatically reviewed. Ambiguous, exclusion-list and unknown-code rows stay pending.
10. Optionally run **Run sanitization** for a local ZIP. In an Alice-only run, all Bob CAS
    members must remain byte-for-byte unchanged. Offline upload-artifact preparation must
    contain only Alice CAS, even for unchanged documents. No remote upload has been validated.

### Expected counts

| Measurement | Both annotators | Alice only |
|---|---:|---:|
| Documents | 3 | 3 |
| Concept annotations (excluding Sentence/Token) | 14 | 7 |
| Inclusion-list findings | 8 | 4 |
| Exclusion-list findings | 2 | 1 |
| Total findings / generated suggestions | 10 | 5 |
| Rule decisions (Number + Date) | 4 | 2 |
| Actual policy overrides (Date) | 2 | 1 |
| Additional automatic selections (Legacy amber) | 2 | 1 |
| Selected changes after rules + conditions | 6 | 3 |
| Pending manual review rows | 6 | 3 |
| Offline upload CAS artifacts | 6 | 3 |

Rules reserve the Number findings in review, so those generic suggestion rows are hidden
rather than counted twice. Date has no generic finding. Consequently the both-annotator
review contains 8 generic rows plus 4 rule rows, not 10 plus 4.

All unselected annotations, literals, notes, text and offsets remain unchanged in local
write-back. A new shared scope can invalidate prior review progress/scans; rerun/reapply
rather than treating an old narrower scan as a complete broader result.

## Reproduce / verify offline

From the repository root:

```bash
PYTHONUTF8=1 .venv/Scripts/python -m unittest test.test_synthetic_annotator_dataset
PYTHONUTF8=1 .venv/Scripts/python test/create_synthetic_annotator_dataset.py --output path/to/NEW-directory
```

The generator refuses to overwrite an existing fixture asset. It creates the seven generated
assets, not this README. Tests exercise the real checker, resolver, rules, automatic conditions,
GUI clicks (both scopes), local ZIP write-back, and offline artifact preparation. They verify
that Bob is untouched/excluded in the Alice-only path and that non-ID features are preserved.

Local knowledge consulted: `okf/snomed-post-processing/data/inception-cas-and-zip.md` and
`okf/snomed-post-processing/workflows/sanitization-suggestions.md`.
